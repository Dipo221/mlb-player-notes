# 球員頁製作 SOP

這份 skill 是「做一頁球員頁」的標準作法，風格已定案為 **C 數據雜誌＋依球隊配色**
（比較過的三個範例在 `design/style-samples/`）。專案層級的規則（資料夾、命名、首頁、禁止事項）以根目錄 `CLAUDE.md` 為準。

## 一、分工：資料區塊 vs. AI 文字

| 部分 | 誰負責 | 怎麼產生 |
|---|---|---|
| 球員英文名（`<title>`、`<h1>`）、背號方塊、位置投打、基本資料、數據表、球種長條、資料來源、首頁卡片 | 腳本 | `scripts/new_page.py`（內容來自 `raw/players/<slug>.json`） |
| 一句話定位、生涯簡介、數據解讀、打法特色文字 | AI | 依本檔第三節撰寫，取代頁面中的 `TODO-AI` |
| 我的觀察 | 使用者 | AI 只負責照原話放入 |

`<!-- data:xxx:start -->` 與 `<!-- data:xxx:end -->` 之間是資料區塊，**不可手改**；要更新就重跑腳本。
`check_site.py` 會重新計算資料區塊並逐字比對，手改一定會被抓到。

## 二、步驟

```bash
python3 scripts/fetch_player.py "Paul Skenes"     # 1. 抓資料 → raw/players/<slug>.json
# 2. 建立 raw/players/<slug>.md（格式見第五節）
python3 scripts/new_page.py paul-skenes           # 3. 用 template.html 產生頁面骨架
# 4. 把頁面裡所有 TODO-AI 換成內容（第三節）
python3 scripts/new_page.py paul-skenes --card    # 5. 印出首頁卡片與應放的分組
# 6. 把卡片貼進 index.html（規則見 CLAUDE.md 第 7 節），更新「共 N 位球員・最後更新」
python3 scripts/check_site.py                     # 7. 必須「全部通過」
```

更新既有球員：`fetch_player.py` → `new_page.py <slug> --update`（只換資料區塊）→
重讀數據表，若「數據解讀」「打法特色」引用的數字已經變了，要一起改寫 → 重新產生卡片並替換首頁上的舊卡片 → `check_site.py`。

## 三、文字段落寫作規則

所有事實與數字都必須能在 JSON 找到；JSON 沒有的寫「待確認」或乾脆不寫。不要用「據說」「可能是因為傷勢」這類 JSON 沒有根據的推測。

### 球員名字
- 一律用英文全名，由腳本從 JSON 帶入 `<title>` 與 `<h1>`，不要改成中文譯名。
- 文字段落中提到球員本人時，也用英文名（或直接省略主詞），例如「Judge 2024 年 58 轟」。

### 一句話定位（`.tagline`）
- 30 字以內，講「他是什麼樣的球員」，最好包含一個可查證的身分標籤（獎項、位置、特色）。
- ✅ 連兩年美聯賽揚、控球與三振兼具的左投王牌
- ❌ 史上最偉大的投手（無法查證、太誇張）

### 生涯簡介（`#bio`）
- 3～5 句，依時間順序：選秀（年份、輪次、順位、球隊、學校）→ 初登板日期 → 主要獎項 → 近三季轉隊。
- 獎項只挑大獎：MVP、賽揚、新人王、金手套／白金手套、銀棒、漢克阿倫獎、世界大賽冠軍、All-MLB、明星賽（多次時合併寫「連續 N 年」）。
- 不寫週／月最佳球員這類小獎。
- 轉隊只能寫「球季中從 A 隊轉到 B 隊」，JSON 沒有交易細節，不可寫成「被交易」「自由球員簽約」。

### 數據解讀（`#analysis`，固定 3 點）
- 格式：`<li><b>小標題：</b>說明。</li>`，小標題 15 字以內。
- 每點至少引用一個表格裡的具體數字，並說明這個數字代表什麼。
- 建議角度：最強的能力、三季的變化趨勢、一個值得注意的異常（例如 ERA 和 FIP 差很多、出賽數大減）。

### 打法特色（`#style`）
- 打者四項，格式 `<li><b>力量</b>…</li>`：**力量**（HR、SLG）、**選球**（BB%、K%）、**速度**（SB）、**守備**（位置、金手套等獎項；JSON 沒有守備數據就說明沒有）。
- 投手兩項：**控球**（BB/9、BB%）、**角色**（先發／後援、局數）。球種已經由腳本畫成長條圖，文字不要重複列球種。
- 二刀流：打者四項＋投手兩項，共六項。

## 四、我的觀察（`#mine`）

- 使用者沒給：維持 `<p class="todo">待補</p>`。
- 使用者有給：把 `<p class="todo">待補</p>` 換成下面的格式，原話只能補標點，不可改寫或擴寫。

```html
<blockquote>使用者原話。<cite>2026-11-16</cite></blockquote>
```

- 之後再補觀察時，在舊的 `<blockquote>` 下面新增一則，日期寫當天，舊的不刪。
- 同時把原話加到 `raw/players/<slug>.md` 的「我的觀察」段落（附日期）。

## 五、raw/players/<slug>.md 格式

```markdown
# English Full Name

- 新增日期：YYYY-MM-DD
- 來源：使用者指令原文（例如「新增球員：Paul Skenes」）
- 數據：見同資料夾 `<slug>.json`（scripts/fetch_player.py 產生）

## 我的觀察

<!-- 使用者原話照貼，只能補標點；新觀察依日期往下加，不覆蓋舊的。 -->

- YYYY-MM-DD：原話（沒有就寫「（待補）」）

## 使用者提供的其他素材

（使用者貼的連結、文章摘錄；沒有就寫「（無）」）
```

## 六、風格速查（已定案，改動前先問使用者）

- 白底、細線、系統字型；重點色＝球隊主色 `--team-primary`，輔助色＝球隊副色 `--team-secondary`。
- 球隊色只在 `<main class="page player" style="--team-primary:…; --team-secondary:…">` 設定一次（腳本會自動帶入），
  頁面頂部色帶、背號方塊、段落標題左線、表頭底線、球種長條、強調文字會自動跟著變色。
- 頁面不可有 `<style>`，行內 style 只允許 CSS 變數；所有樣式寫在 `assets/css/site.css`。
- 支援深色／淺色模式（`assets/js/theme.js`，版型的 `<head>` 已載入）。文字與線條的球隊色用 `--accent`，色塊才用 `--team-primary`，深色模式才不會看不清楚。
- 版型骨架在同資料夾的 `template.html`。要改版型時先改 template 與 site.css，並請使用者確認；
  既有頁面的資料區塊可用 `--update` 重新產生，其他結構（段落、標題）要手動同步到每一頁。
